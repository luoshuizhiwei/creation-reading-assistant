# 后续单任务执行单模板

本模板用于接任协调者给其他agent落盘任务。先读[current](current.md)和[接续手册](continuation-playbook.md)。复制到该轮实际任务文档后填写；未填写不是可执行合同，不能拿占位符触发设备或发布。

## 派发总览

| 字段 | 本轮填写 |
|---|---|
| 任务编号/版本、日期 | 未填写 |
| 状态 | 草案 / 已授权待执行 / 执行中 / 待核验 / 部分接受 / 已接受 / 阻塞 / 暂缓，选实际状态 |
| 用户本轮指令及操作范围 | 未填写；明确是否解除暂停，哪些操作仍禁止 |
| 协调者 / 实施owner / 核验者 | 未填写；可以由接任agent承担，非必须原Root |
| 推荐模型与替代、复杂度 | 未填写；按当前实际可选资源，不虚称切换 |
| 预计耗时、预算与起算方式 | 未填写；实际派发未知不得填假时间 |
| 依赖与并行/等待 | 未填写；同candidate/Gradle/设备唯一owner |

## 完整交给执行者的任务正文

````text
任务编号/版本：【填写】。这是实际执行单，必须所有必填内容齐全后才派发。

1. 目标与成功标准
【填写具体用户流程、触发条件、期望与本轮证据边界；不能只写“修好”。】

2. 基线与启动读取
活动仓库D:/develop/Code/Codex/creation-reading-assistant-recovery-20260919。
先读AGENTS/current及本任务直接原报告；旧路径查docs/document-map.csv。
【填写输入绝对路径、size/SHA/版本、实际环境；未知明确列出。】

3. 可写范围与资源所有权
【列精确文件/目录、变更目的、candidate/Gradle/设备owner；列冻结/只读对象。】
你不是独占全库，不能回滚/覆盖他人WIP。实际SHA/owner冲突停依赖动作并报告。

4. 权限与停止点
【分别填写源码、构建、设备、ADB/VM、恢复、电脑代发、自动化、Git、资产删移、发布是否获本轮授权。】
不要从历史成功、原Root离线或此模板推导权限。用户明确同批授权不重复问。

5. 步骤与依赖
【逐项写真实入口、参数来源、操作先后、预期输出；失败怎么保全/安全恢复。】
【明确哪些步骤不能并行；独立工作如何与集成owner交接。】

6. 验证
【填写最小充分的定向目标/命令、原rc/log/XML、红→绿的判据。】
充分同输入旧证据引用原路径，不重复全suite；失败保留原红，不改断言/超时迎合通过。
【设备任务必须单列fresh身份/数据/APK/设置基线及完整恢复；无权限则NOT_RUN。】

7. 输出与存储
报告根：【任务专用E盘绝对路径】。
必交REPORT.md、ready.json、最小patch/改动源码、前后SHA和必要原日志/XML/产物pins。
【填写源码/报告/ready上限、raw上限、预计新增bytes、唯一保全例外及现有环境锁。】
不复制工程、依赖/cache、历史证据或已有唯一APK保全，不删移原件。
ready最后生成，列真实路径/size/SHA、不自引用。原报告/失败不得覆盖为通过。

8. 预算/异常/交接
【填写预算到点必须交哪些部分成果、具体缺口、恢复不中断与安全停止条件。】
完成后向用户或指定接任协调者报告，不等待原窗口额度恢复。由接任协调者核原证后推进。
下一轮前更新current/state与对应合同，确保只读文档可接续。
最后独立一行：这是任务【实际编号及版本】。
````
