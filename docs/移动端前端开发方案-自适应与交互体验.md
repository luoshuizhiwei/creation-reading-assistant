# 移动端前端开发方案 · 自适应体系与交互体验

> 项目：创作阅读助手（Capacitor 6 + React 18 + 自研 MD3 暖铜设计系统，真安卓应用）
> 范围：**移动端 `mobile/`**，不涉及桌面端 `src/`，不接入 `creation-reading-assistant-mobile-ui/` 的 HTML 稿
> 目标：在已完成的 P0–P3 视觉地基之上，补齐「响应式 / 自适应」与「良好的用户交互体验」
> 状态：**方案阶段，未改动任何源码**（本轮只产出本文档）

## 0. 一句话结论

P0–P3 视觉美化已经做完，门面页、分类色封面、状态胶囊、毛玻璃导航、阅读器走纸感都已在位。**现在要的不是"再美化一次"，而是两件事：**

1. **把"响应式设计"翻译为移动端的"自适应（Adaptive）"** —— 现网只有 375/390 两个小屏断点，缺大屏/折叠屏/横屏/动态视口/密度缩放的系统性处理。
2. **把"交互体验"拆成"健壮性 + 打磨"** —— 先堵住会直接伤体验的 bug（首屏白屏、删书卡死、阅读丢时长、进度卡顿、TTS 挂起），再做手势/转场/状态反馈/无障碍的统一。

## 2. 设计原则（延续既有约束）

1. **不破坏现有体系**：沿用 `md3-base.css` 令牌与现有 className 命名，不大规模重命名。
2. **纯 CSS / 设计令牌落地**：新增适配逻辑优先用 CSS 变量 + 媒体查询，零运行时依赖（与 P0 一致）。
3. **不动功能逻辑**：本次只改样式、交互壳层与少量健壮性兜底（try/catch、AbortSignal），不改业务算法。
4. **构建必须通过**：`cd mobile && npx tsc --noEmit && npx vite build` 绿灯。
5. **Android WebView 兼容**：`:active` 用 `transform: scale` 反馈，不用 `background`（背景会粘连）；`backdrop-filter` 必带 `-webkit-` 前缀。
6. **去网页感反模式**（沿用 `移动端设计令牌与组件规范.md` §6）：禁字符箭头、禁 `:hover` 作主反馈、禁过宽容器（>560px）、禁网页式响应式收口。

## 3. 工作流拆解（四大模块）

### 模块 A · 自适应体系（把"响应式"落成移动端语言）
移动原生没有"流式重排"，自适应 = 适配**设备特征**，不是把网页拉宽。

- **A1 尺寸阶梯令牌**：在 `md3-base.css` 补一套 `clamp()` 化的字号/间距/栅格变量，让大屏自动舒展、小屏不挤。
  - 示例：`--app-content-max: min(100%, 560px)` 维持；新增 `--app-gap: clamp(12px, 3.2vw, 16px)`、`--app-h1: clamp(26px, 7vw, 30px)`
- **A2 设备分级断点**（补全现有 375/390）：
  - `≤360` 超小屏：压缩横向 padding、字号下限保护
  - `361–414` 主流：现状基线
  - `415–560` 大屏/平板兼容：双列书格可升 3 列、卡片内边距放宽
  - `>560` 折叠屏/横屏：内容居中 + 两侧呼吸区，不强行拉满
- **A3 横屏适配**：`@media (orientation: landscape)` 下底部导航降高度、阅读器切"左文右控"或保留全屏、Sheet 高度改 `lvh`。
- **A4 动态视口与键盘**：用 `100svh`/`100dvh` 组合 + `interactiveWidget`（Capacitor 可选插件）规避输入法顶起；表单页 `padding-bottom` 走 `env(keyboard-inset-height)` 兜底。
- **A5 密度与字体缩放**：现有 `appFontScale` 仅改 `root.style.fontSize`；补充对图标尺寸、触控目标的最小下限保护，确保大字体下不破版。

### 模块 B · 交互健壮性（先堵会伤体验的洞）
- **B1 首屏兜底（S1）**：`App.tsx:144-150` 加 `.catch`，失败时降级到 localStorage 快照 + 显示错误提示页，绝不空白屏。
- **B2 删书对话框兜底（G2）**：`ShelfPage.tsx:313-318` 的 `onConfirm` 包 try/catch，异常时关闭对话框并报错。
- **B3 阅读会话保全（G3）**："阅读中开灵感"路径先 `leaveReader()` 落库会话再跳转。
- **B4 进度写入瘦身（S3/G7）**：高频 progress 只写 SQLite；localStorage 分支按 `selectedSections` 局部更新，去除每 1.5s 全量 `JSON.stringify`。
- **B5 TTS 健壮性（G4/G5）**：`fetchOnlineTTS` 加 `AbortSignal` + 超时；在线引擎 `play()` 与 `pause()` 状态机对齐 local 引擎。

### 模块 C · 交互体验打磨
- **C1 手势**：阅读器/列表的滑动返回、下拉刷新、Sheet 拖拽关闭（`touch-action` 已部分使用，需补手势识别与阈值）。
- **C2 转场统一**：tab 切换、Sheet 进出、页面进入统一走 `md3-page-enter` 与既有缓动令牌，消除散落的 100–320ms 具体值。
- **C3 状态可视化**：加载（skeleton）、空态（已有 `EmptyIllustration`）、错误（toast + 内联重试）三态在全部列表/网络场景中一致。
- **C4 反馈一致**：所有可点目标 `:active` 缩放 + 可选轻 haptic（`navigator.vibrate` 短振），触控目标 ≥44px 全量核查。
- **C5 无障碍（WCAG 2.1 AA）**：补充 ARIA（`role`/`aria-label`/`aria-live`）、Sheet/Dialog 焦点陷阱与 `Esc`/返回键关闭、屏幕阅读器朗读顺序；对比度已达标，维持。
- **C6 动效偏好**：`prefers-reduced-motion` 已接，扩到所有自定义动画；`prefers-contrast: more` 提供高对比令牌分支。

### 模块 D · 工程化收口
- **D1 CSS 治理**：现有 9 个样式文件（md3-base / app-foundation / app-pages / interaction-polish / reader / release-overrides / shelf-library / tts-player / inspiration-center / unified-layer）职责有重叠，新增内容明确归口，避免再次散落。
- **D2 令牌校验**：把"去网页感反模式"（§6）做成轻量 CI lint（字符箭头、过宽容器、缺 `-webkit-backdrop-filter`），防回归。
- **D3 真机验证清单**：覆盖小屏(≤360)/主流/大屏/折叠屏/横屏 × 亮暗主题 × 字体缩放，作为每阶段验收。

- ✅ 加载/空/错三态在所有列表与网络场景一致
- ✅ 无障碍：WCAG 2.1 AA 对比度达标、Sheet/Dialog 焦点可控、屏幕阅读器可读

- ✅ CI lint 零网页感反模式（字符箭头 / 过宽容器 / 缺 `-webkit-backdrop-filter`）
