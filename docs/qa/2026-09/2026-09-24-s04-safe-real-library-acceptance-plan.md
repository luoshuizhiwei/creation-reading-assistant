## 1. 为什么需要这一层真机验收

S04 的替换链路（`ShelfImporter.reselectEpub` / `reselectPlainText` → `EpubRepository.replaceStoredEpub`）的**进程内异常回滚**与**入口残留守卫**已有 JVM 定向证据（`EpubRepositoryReplaceTest` 10/10）。但 JVM 测试用 mock 的 `Context` / `BookDao` / `ContentResolver`，**不能代表**：

- 真实 SAF `ContentResolver` 的 Uri 权限与 `openInputStream` 行为；
- 真实 SQLite 的写入、`books` / `book_files` / `library_source_refs` 三表推进；
- 真实 `filesDir` 下的文件落盘、`renameTo` 同卷语义、`run-as` 可观测的目录形态；
- 用户在真实书架上的可观察结果（角标、Snackbar、正文可读性）。

因此本方案的目标**不是**替代 JVM 测试，而是补上「真实文件系统 + 真实 DB + 真实 UI」这一环，并且**只碰我们自己新建的隔离测试书**。

## 2. 被测入口与可观察面（供执行者对照）

两条入口都最终落到同一份替换逻辑，**观察面相同**，只是触发手势不同：

| 入口 | UI 路径 | 触发文案（源码事实） |
|---|---|---|
| **来源更新**（自然路径） | 书架下拉刷新 | 弹窗标题「同步源文件更新？」，正文「检测到 N 本书…的源文件已被修改，是否重新同步正文？同步后将重置章节与阅读进度。」，按钮「取消」/「重新同步」；书卡右上角「可更新」角标 |
| **重新定位文件**（修复路径） | 书卡菜单 →「重新定位文件」 | 副标题：`READY` 时「更换本地文件并保留阅读记录」，否则「修复缺失的本地正文」；成功后 Snackbar「《书名》正文已修复」 |

替换失败时，错误经 `ShelfImporter` 的既有 catch 冒泡为「修复失败：<message>」。残留守卫在 `EpubRepository.kt` 与 `ShelfImporter.kt` 各有一处、语义一致。

**该提示语是条件式的，不要依赖任何硬编码引文。** 守卫面对两种现场：`target` 存在（旧正文仍在）与 `target` 缺失（旧正文已挪进 `.backup`）。因此任何版本都**不得**断言「原有文件已保留」——`target` 缺失时并不存在这样一份文件，那样写会让用户误以为旧正文还在原处。

执行者应按下列**稳定不变量**核对（措辞可再变，语义不应变）：

1. 点明「**检测到未完成的替换残留**」；
2. 点明「**本次替换已停止**」；
3. 对旧正文**有条件**表述：**若仍存在**，则未被本次操作修改（**不**承诺 `target` 一定还在）；
4. 点明残留备份**已保留**（不删）；
5. 点明**重复重试不会自动恢复**该备份，且不暗示存在自助恢复入口。

> **快照（截至 2026-09-24 16:31，仅供对照，可能再次变更）**：
> 「检测到未完成的替换残留（`<id>.backup`），本次替换已停止；旧正文若仍存在，则未被本次操作修改，残留备份已保留。重复重试不会自动恢复该备份」
>
> ⚠️ **执行前必须核对最终构建版本**：该文案已先后改动两次（旧版曾写「…已停止本次替换以免覆盖可能完好的旧正文；请先在书架中确认该书内容，再重试」，因暗示「重试即可恢复」而不准确；随后又改为「原有文件与备份均已保留、未被改动」，因 `target` 缺失时该断言不成立）。**方案不得依赖上述引文**：执行者开始前须重新读取两处源码，以**与待测 APK 同版本**的实际字符串为断言依据；报告中记录**实际观察到**的字符串。

## 3. 隔离原则（不可协商）

1. **不修改用户既有书；改动只限新建的隔离测试对象**：测试对象只能是在隔离目录里**新导入**的「测试 TXT」「测试 EPUB」。不得选、不得改、不得重导任何既有书。
   > **措辞更正（原写「只新增、不改动」不准确）**：所谓「不改动」只在**既有书**这一层成立。隔离测试对象本身是会被改动的，至少包括：
   > - 隔离目录里的**测试源文件会升级到 V2**（§6 层 1 的第 1 步）；
   > - 应用会为测试书写 **DB**（`books` / `book_files` / `library_source_refs` / `book_contents`）并触发**搜索索引重建**；
   > - 若测试书有阅读位置，`reading_progress` 也可能变化（见 §6 层 1 的进度项）。
   > 这些改动都落在**我们自己新建的**测试对象上，不涉及用户既有书 —— 这才是本方案要保证的边界。
2. **不删除用户书库**：不删除、不重置、不重导任何既有书；**不使用设备端通配符删除**（如 `rm -rf .../books/*`）。任何清理命令都必须点名具体文件。
3. **只读取证为主**：DB / DataStore / 内部文件一律 `run-as cat` 复制到主机后离线只读查询，**不回写设备**。唯一的例外是 §6 的合成残留（须确认）。
4. **测试书默认保留**：与 S04 先例一致，隔离测试书及其外部来源测试文件**默认留在手机**，未经用户明确授权不删除。
5. **脱敏**：报告、截图、命令输出中一律只写「测试 TXT」「测试 EPUB」等中性称呼；**不记真实书名**、不记用户私有父目录名。截图必须遮盖真实封面与标题后再入仓。

## 5. 测试前快照与恢复点

**顺序**：先停应用确保事务落盘 → 再导出 → 再记录基线 → 才开始任何 UI 操作。

1. **停止应用**（避免导出到半写状态）
   ```
   adb -s <serial> shell am force-stop com.creationreadingassistant
   ```
2. **指定范围的恢复点**（仓库外私有目录，不上传、不提交）
   ```
   cmd /c "adb -s <serial> exec-out run-as com.creationreadingassistant tar -cf - -C /data/data/com.creationreadingassistant databases files shared_prefs > <仓库外私有目录>\cra-s04-guard-backup-pre.tar"
   ```
   记录**文件大小**与 **SHA-256**。这是本方案**唯一**的恢复点，但它**只覆盖下列三个顶层目录**，**不是**整个应用数据的「全量备份」：

   | 已覆盖 | 说明 |
   |---|---|
   | `databases/` | Room DB 与 WAL / SHM |
   | `files/` | 内部正文副本、字体、TTS 缓存、词库等（见下） |
   | `shared_prefs/` | 共享首选项 |

   | **未覆盖**（必须写进报告，不得省略） | 说明 |
   |---|---|
   | `cacheDir`（`cache/`） | 未导出；含 `cache/books/<bookId>` 同步中转、`cache/dictionary-cache`、`cache/epub/<id>.epub` 迁移回退等 |
   | 应用外部目录 | `getExternalFilesDir` / `externalCacheDir` 下的数据（若存在） |
   | 应用私有目录**之外**的一切 | **用户 SAF 书库**中的原始来源文件、SAF 权限状态等 |
   | 设备级状态 | `stay_on_while_plugged_in`、通知权限等系统设置 |
   | 其他应用 / 系统数据 | 不在本方案范围 |

   | **已包含，但仅保存原始二进制**（不得据此宣称已验证 DataStore 语义或恢复演练） | 说明 |
   |---|---|
   | `files/datastore/*.preferences_pb` | 因 `tar` 整体导出 `files/`，这些 DataStore 二进制文件**已随 `files/` 进入归档**；但归档只保存了原始字节，**不等于**已验证 DataStore 语义、也不等同于做过恢复演练。核对只能按**文件**逐份比对字节 / 时间戳，不能当作「已覆盖」DB 语义 |

   > ⚠️ **边界声明（不得放宽）**：该恢复点是「指定范围的恢复点」，**不得**称为「应用数据全量备份」，也**不得**声称它能恢复未覆盖目录中的任何内容。报告中引用它时必须连同上表一起给出。
3. **既有书清单（只读，不读内容）**
   ```
   adb -s <serial> shell run-as com.creationreadingassistant ls -la files/books/
   adb -s <serial> shell run-as com.creationreadingassistant ls -la files/books/epub/
   ```
   只看**文件名与时间戳**，不记录书名。
4. **既有书基线摘要**：从导出的 DB 副本离线计算 `books` / `book_files` / `reading_progress` / `library_source_refs` 中**既有书**所选字段的 SHA-256 摘要（参照 S04 先例的 `verify_*.py` 做法）。
   > ⚠️ **边界声明（必须照此措辞，不得放宽）**：该摘要**只能证明「这些被选字段一致」**。
   > - **不能**扩大为「用户所有数据零变化」——未覆盖的表、未选的列、原有外部来源文件、DataStore、封面缓存等都不在摘要内；
   > - **不能**无条件写成「既有书零变化」——摘要只覆盖选定字段，措辞须限定为「既有书**所选字段**摘要一致」；
   > - 若报告要主张更强结论，必须**逐项列出**被覆盖的表 / 列，否则按未覆盖处理。
5. **隔离测试书自身的基线**：记录其内部副本路径、字节数、MD5、以及 `books` / `library_source_refs` 的 `content_hash`。
6. **记录 DataStore 只读副本**：`files/datastore/app_settings.preferences_pb`、`files/datastore/import_history.preferences_pb`（导入/修复历史，用于核对失败是否留下假记录）。

**恢复点使用规则**：仅在发生用户数据破坏且**用户明确要求回滚**时使用；**只能恢复 §5.2 表中已覆盖的目录**，未覆盖项（`cache/`、外部目录、SAF 书库等）无法由它恢复；回滚前必须 `force-stop`，回滚本身是实质性设备操作，**须单独确认**。

## 6. 分层验收矩阵

> 每一层：**目的 → 前置 → 操作 → 可观察证据 → 判定 → 停止条件**。
> 命令中的 `<serial>` 与 `<bookId>` 由执行者现场填入；`<bookId>` **不得**写入公开报告。

**两阶段安排（重要）**

| 阶段 | 内容 | 前置 |
|---|---|---|
| **阶段 A · 可先做** | **层 1**（正常替换）+ **层 2**（来源被拒后原正文仍可读）。只需新建隔离测试对象，**不触碰用户既有书** | 用户确认 §4.3 **U1 / U2** |
| **阶段 B · 需另行决定** | **层 3**（残留守卫）。必须在应用**私有目录**手工合成 `.backup` 残留，属实质性设备写入 | 用户**单独确认** §4.3 **U3 / U4**（并明确 U5 是否清理测试书） |

> 阶段 A 与阶段 B **互不依赖**：层 3 的合成残留是独立动作，不要求先跑完层 1 / 层 2；但建议按 A → B 顺序，便于先用正常路径确认测试书本身是健康的。

### 层 1 · 正常替换（自然路径，安全）

**目的**：证明真实环境下替换成功、正文更新，且**既有书的所选字段**保持一致（不主张既有书整体「不受影响」，见 §5.4 边界）。

**前置**：§5 快照已完成；隔离测试书已导入。

**操作（TXT 与 EPUB 各做一遍）**

1. 在隔离目录把测试源文件替换为 V2（追加可识别的新标记词），使 size / mtime 推进。
2. 书架下拉刷新 → 出现确认弹窗 → 点击「重新同步」。
3. 用书卡菜单 →「重新定位文件」再做一次（覆盖**修复入口**）。
   > 两条入口走的是**同一份替换逻辑**，但**证据面不同**：`library_source_refs` 基线与单书搜索索引重建只发生在**来源更新**路径（`refreshFromSource` → `refreshSourceBaseline` + `indexRefreshCoordinator`）；「重新定位文件」直接走 `repairFileTyped` → `reselect*`，**不**推进来源基线。因此上表 `library_source_refs` 一行**只对第 2 步适用**，第 3 步只核对内部副本与 `books` / `book_files`。

**可观察证据**

| 证据 | 命令 / 位置 |
|---|---|
| 内部副本已更新 | `run-as ls -la files/books/<bookId>/…`（TXT）或 `files/books/epub/<bookId>.epub`（EPUB）字节数 = V2 |
| 内部副本内容 | `run-as cat` 复制到主机后算 MD5 = V2 MD5 |
| DB 三表推进 | 离线只读查询：`books.size` / `content_hash`、`book_files.size`、`library_source_refs.size` / `content_hash` / `last_modified` |
| 角标清除 | 截图：「可更新」角标消失 |
| 正文可读 | 打开测试书，读到 V2 标记词 |
| 进度行为（**实测，不得预设**） | **源码事实**：替换链路 `ShelfImporter.reselectEpub` / `reselectPlainText` **不写** `reading_progress`（该 DAO 不出现在 `ShelfImporter` 中）；但确认弹窗文案却声称「同步后将重置章节与阅读进度」——**文案与代码不一致**。⇒ 必须实测该测试书 `reading_progress` 行的**内容与 `updated_at`** 前后对照，记录**实际**行为。**禁止**把「行还在」写成「进度保留」：行存在**不等于**进度未变，必须给出字段级前后对比 |
| 既有书**所选字段**一致 | 重算 §5.4 摘要，与基线一致；`run-as ls` 清单时间戳未变（措辞见 §5.4 边界：**不得**写成「既有书零变化」或「用户所有数据零变化」） |
| 导入历史无假记录 | 只读解析 `import_history.preferences_pb`，成功路径只有 1 条 success |

**停止条件**：若 `books.content_hash` 与 `library_source_refs.content_hash` 不一致（S04 曾出现的 P2 陈旧哈希），**立即停止**，保留现场，不在本轮尝试修复。

### 层 2 · 失败后原正文仍可读（真机可安全覆盖的失败环）

**目的**：证明**来源被拒**时，**测试书**的内部正文逐字节未变、其相关 DB 行未推进（范围限**该测试书**；不主张整个书架状态不变）。

> ⚠️ **覆盖边界（必须写进报告）**：真机能安全触发的只有**「替换开始前来源即被拒」**这一类失败。它**不**覆盖「target 已被改写后回滚」那一环 —— 后者需要故障注入，**只能留在 JVM**（§7）。

**三种安全注入**（都不触碰 target）

| 注入 | 做法 | 预期异常来源 |
|---|---|---|
| 损坏来源 | 在隔离目录放一个非合法 ZIP 的 `测试 EPUB`，走「重新定位文件」 | `EpubParser.parse` 抛错（`不是合法的 EPUB…`） |
| 格式不符 | 对一本测试 TXT 选一个 EPUB 文件（或反之） | `格式不一致：原书为 TXT，所选为 EPUB` |
| 空来源 | 放一个 0 字节测试文件 | 「所选 EPUB 没有可读取的正文」/「文件内容为空」 |

**可观察证据**

- 出现「修复失败：<message>」，且 message 与上表对应；
- 内部副本**字节数与 MD5 均与失败前完全一致**（逐字节断言，不能只比长度）；
- 打开测试书，**正文仍可读**（原 V1 内容）；
- **测试书**的 `books` / `library_source_refs` **零推进**（只对该测试书成立，不外推到全库）；
- 既有书**所选字段**摘要不变（措辞受 §5.4 边界约束）；
- 中间态 `.repairing` **不得残留**。

**判定**：以上全部成立 ⇒ PASS（限「来源拒绝」这一环）。

**停止条件**：若内部副本字节发生变化，立即停止、保留现场（§9）、上报为数据风险。

### 层 3 · 残留备份守卫（**需用户确认**，见 §4.3 U3/U4）

**目的**：证明操作开始前已存在 `.backup` 时，替换被**拒绝**、target 与 backup **均逐字节保留**、DB **零写入**、**不自动恢复**。

#### 6.1 残留的**安全**合成方式（唯一允许的做法）

**只能**通过**复制**完好的 target 得到残留：

```
# 仅对隔离测试书；<safeName> 为 TXT 的内部文件名，EPUB 则为 <bookId>.epub
adb -s <serial> shell run-as com.creationreadingassistant \
  cp files/books/<bookId>/<safeName> files/books/<bookId>/<safeName>.backup
```

- **绝不允许**用移动 / 删除 target 的方式制造残留（那会真的丢掉唯一副本，属被禁止的「破坏真机数据」）。
- 复制前后都记录 target 的**字节数与 MD5**，证明合成动作本身没有改动 target。
- TXT 与 EPUB **各测一次**（两种残留命名不同：`<safeName>.backup` vs `<bookId>.backup`）。

#### 6.2 操作

合成残留后，对同一本测试书执行一次替换（下拉刷新 →「重新同步」，或「重新定位文件」）。

#### 6.3 可观察证据

| 证据 | 预期 |
|---|---|
| 错误文案 | 出现含「**未完成的替换残留**」的失败提示，且满足 §2 的五条**稳定不变量**（条件式表述旧正文、不承诺 `target` 一定还在）；**以实际构建版本为准**，不比对硬编码引文 |
| target 未变 | 内部副本字节数 **与 MD5 均等于**合成前 |
| backup 未变 | 残留 `.backup` 仍存在，字节数 **与 MD5 均等于**合成时 |
| DB 零写入 | `books` / `book_files` / `library_source_refs` 均未推进 |
| 不自动恢复 | target 未被 backup 内容覆盖（MD5 比对可证） |
| 正文可读 | 打开测试书仍读到原内容 |
| 既有书**所选字段**一致 | 摘要与基线一致（措辞见 §5.4 边界） |

#### 6.4 还原

用 `run-as` 删除**我们自己创建的**那个 `.backup`（**点名具体文件，禁止通配符**），再确认 target 的 MD5 仍等于合成前。

#### 6.5 停止条件

若 target 或 backup 任一被改动、或发生自动恢复，**立即停止**并保留现场。

## 7. 只能留在 JVM / 隔离环境的危险情形

以下情形**不得**在用户真实书库上尝试（会真实丢正文或需要不可逆的进程杀死 / 断电）：

| # | 情形 | 为什么不能上真机 | 现有覆盖 |
|---|---|---|---|
| D1 | `renameTo(backup)` 失败 → `copyTo(backup)` **中途失败** | 需要强制 `renameTo` 失败，真机无注入接缝 | **当前无覆盖**（已登记的缺口，见残留守卫报告 §5.2） |
| D2 | 后置持久化失败 ⇒ 从 backup 逐字节还原 | 需让 DB 写失败 | `EpubRepositoryReplaceTest`「restores original target bytes from backup…」 |
| D3 | 协程取消 ⇒ 回滚 | 需在持久化阶段抛取消 | 「still rolls back the file when the caller is cancelled」 |
| D4 | 进程被杀 / 断电残留（K2/K3/K4） | 真机只能靠**真的杀进程 / 断电**制造，属破坏性 | 设计稿 §4 的 N 系列规则**未实现**；本片只做入口拒绝 |
| D5 | 大文件（>32 MiB）`content_hash` 置 null | 真机造 32 MiB 文件占空间且拖慢 | 「clears content_hash to null for large files over 32MiB」 |
| D6 | `renameTo` 跨卷 / 权限失败 | 需构造跨卷或权限拒绝环境 | **无覆盖** |
| D7 | 同一本书被两个入口**并发**替换 | 真机并发时序不可控 | **无覆盖**；设计稿 §7.6 列为未设计 |
| D8 | 备份复制长度校验 `require(backup.length() == target.length())` | 需 copyTo 部分写入 | **从未覆盖**（已登记缺口） |

> 上表与残留守卫报告 §5.2 的「失去的分支覆盖」一致：本方案**不**用真机去补这些缺口，也**不**把真机结果冒充为它们的覆盖。

## 9. 失败时如何保留现场

一旦出现下列任一信号，**立即停止后续步骤**，只做**只读**取证：

1. 内部副本字节数或 MD5 与预期不符；
2. 既有书摘要与基线不一致；
3. 出现自动恢复（target 被 backup 覆盖）；
4. `books.content_hash` 与 `library_source_refs.content_hash` 不一致；
5. 出现非预期的 `.repairing` / `.backup` 残留。

**保留现场的做法（全部只读）**

- 不删任何文件、不回滚、不重试、不卸载、不 `pm clear`；
- 立即 `force-stop`（防止后台继续写）；
- 导出**现场**快照（与 §5.2 同命令，落到**另一个**文件），记录 SHA-256；
- 记录 `run-as ls -la files/books/` 与对应 EPUB 目录的清单（名字 + 时间戳）；
- 截图（脱敏后入仓）；
- 在报告中如实写「失败 + 现场已保留」，并交由**开发窗口**判定，不由验收窗口自行修复。
