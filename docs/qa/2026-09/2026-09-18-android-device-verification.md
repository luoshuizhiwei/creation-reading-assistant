## 1. 翻页动画（用户报：闪一下、顿一下、快翻空白）

**根因（两处，都在 `pager/PageTurner.kt`）**

1. **闪 + 顿**：`settle()` 里 `onNext()` 换帧发生在位图轮换**之前**，而渲染分支判定读的是
   **实时** `currentFrame`。最后一帧出现「帧已换、位图未换」的错位 → 位图就绪判定翻为
   false → 渲染从位图分支掉回实时分支，该帧要当场组合整页正文（十几~几十毫秒）。
2. **快翻空白**：兜底分支只给邻页自身套纸色，邻页为 null（跨章尚未预排）时什么都不画，
   当前页滑走后露出底层背景。

**修复**：新增 `TurnScene` 快照，拖拽/动画起点冻结参与本次翻页的三帧，动画全程只读快照；
兜底分支父容器常驻不透明纸色。

**验证**：`screenrecord` + `ffmpeg` 逐帧（60fps，541 帧）分析「仿真覆盖」连续翻页：
- 空白帧（页面区域标准差 < 12）：**0 个**
- 帧间差异最大值 13.6，无突变 → 无闪烁

## 2. 夜间模式冷启动（用户报：进应用闪成日间再回夜间）

**根因**：那一帧由 system_server 在应用进程启动**之前**按 manifest 主题创建，
`Activity.onCreate` 里的 `setTheme()` 改不到它；`values-night/` 只在**系统**深色时生效。
用户场景是「系统浅色 + 应用内设深色」，因此仍走浅色主题。

**修复（三层）**：
1. `UiModeManager.setApplicationNightMode`（API 31+）把选择交给系统 —— 下次冷启动系统
   即按深色解析启动窗口；写在主题写路径 + `App.onCreate` 收敛。
2. `setTheme(Dark)` 兜住 API 31 以下。
3. `values-night/themes.xml` 覆盖「跟随系统 + 系统深色」；manifest 的 `configChanges`
   补 `uiMode`，避免切深浅重建 Activity。

**验证**：冷启动录像逐帧分析。
- 修复前：frame 35–47（约 **0.4 秒**）为浅色 `#F6F2EA`。
- 修复后：**无浅色帧**（MID → DARK，无 LIGHT 段）。

## 3. 导入页排序（用户报：没有按最近添加等排序）

**根因**：`LibraryBrowserViewModel.setSortMode()` 写完 DataStore 后立刻回读
`rootStore.root.value`，而该 StateFlow 由 ApplicationScope（IO）异步发射，写入返回时
读到的仍是**旧值** → 重列继续用旧排序 = 「点了排序没反应」。

**修复**：`loadDirectory()` 增加 `sortMode` 参数显式传入；并乐观写本地 `core` 让选中态立即响应。

**新增排序项**：「最近添加」。**注意**：SAF 只提供 `COLUMN_LAST_MODIFIED`，系统层面没有
「文件加入文件夹的时间」；文件拷入目录时其修改时间即拷贝时间，故与「修改时间」同键。
两项并存是因为用户按不同心智检索，文案差异有意义（已在 `LibrarySortMode` KDoc 说明）。

**验证**：真机切「最近添加」后列表严格按时间倒序（08-13 → 08-11 → 07-21 → …），
首项由「名称」序的 04-28 变为 08-13。

## 4. 导入页搜索（验证中发现的新缺陷）

**根因**：`uiState` 里 `files` 过滤了关键词，`directories` 原样透出 —— 搜只匹配文件的词时
所有文件夹仍列出，用户看到「搜了没反应」。

**修复**：两侧用同一匹配规则过滤；并把空态区分为「搜索无结果」（提示改关键词）与
「目录本身为空」（提示换目录）。

**验证**：输入 `yellow` 后只剩匹配的文件夹，其余不再出现。

## 5. 页面重建（MD3 结构 + 本项目既有风格）

只借 legado-with-MD3 的**信息架构**，视觉全部复用本项目组件（`SectionCard` /
`SelectablePill` / `PillShape` / `LocalLayoutTokens` / 既有色板与 32dp 微彩底座范式）。
排序由列表内一行胶囊改为顶栏溢出菜单（4 项带勾）；路径由顶部面包屑改为**底部路径栏**；
搜索改顶栏按需展开；返回键分层（搜索 → 选择 → 上级 → 退出）。

**过程中修掉两个自引入缺陷**（真机复现）：
- 路径栏初版用 `SectionCard` 承载，其内部 `Box(fillMaxSize)` 吃掉整屏高度约束 → 卡片撑满
  盖住列表。改为定高条。
- 浮动脉络条四周露出滚动中的列表文字 → 改为不透明贴底 + 顶部发丝线。

## 8. 环境备忘（供后续真机验证复用）

- **MIUI 安装确认**：`adb install` 会弹 `AdbInstallActivity`，6 秒倒计时后自动拒绝。
  解法：后台起 install → sleep 3 → `input tap 351 2522` 点「继续安装」。
- **中文输入**：微信输入法下 `input text` 与 keyevent 都写不进 EditText；切
  `com.sohu.inputmethod.sogou.xiaomi/.SogouIME` 后可用，**测完必须切回 wetype**。
- **瞬时问题取证**：`screenrecord` + `ffmpeg -vf fps=60` 逐帧 + PIL 算亮度/方差，
  比逐张 `screencap` 可靠（后者每次约 0.3s，抓不到动画中间帧）。

## 9. 用户真机反馈 7 项（2026-09-19 追加）

用户在 Mate 70 Pro 实测后反馈 6 项 + 新增 1 项。全部定位并修复，关键项已在 Redmi 复验。

### 9.1 灯绳偏粗、不随主题变色 —— 已修
- 绳身 9dp → 7dp，控件宽 30dp → 24dp（坠子按比例同步缩小）。
- 绳身改用**外壳主题主色**（`MaterialTheme.colorScheme.primary`），线圈缝用 onPrimary ——
  此前从纸张前景色派生，换配色主题时绳子不跟主题走，且与菜单栏不成一套。

### 9.2 页眉页脚电量显示重叠 —— 已修
- 「电量内显」原版把 7sp 数字压进 21dp 电池腔体，真机上数字与轮廓互相重叠、大半被盖住。
- 改为**图标与数字并排**（间距 3dp、数字 10sp），互不遮挡；电量格仍在腔体内按电量填充。

### 9.3 书籍目录路径栏位置 —— 已撤回顶部
- 上一轮按 MD3 参考样本把路径栏移到了底部；用户反馈「不符合操作习惯」。
- 原设计（方案 6.2）本就明确**不照搬**参考项目的底部路径栏 —— 本次撤回并记录，
  该决策是对的。路径栏回到列表顶部（根目录卡下方），保留轻量胶囊样式与「上一级」。

### 9.4 书籍目录刷新看不到新文件 —— Redmi 上验证为正常
- 真机复现路径：授权测试目录（3 个文件）→ adb 推入新 TXT → 点刷新 → **新文件立即出现**
  并按「最近添加」排在最前。连续两轮验证（两本新书）均通过。
- 结论：代码路径（`reload() → SafLibrarySource.list()` 实时 SAF 查询）没有问题。
  用户在 Mate 70 Pro 上的现象大概率是**系统文件提供器的索引延迟**（经 PC/MTP 拷入的
  文件要等系统索引后才对 SAF 可见）。自查方法：用系统「文件管理」看同一目录，
  若系统里也看不到，就不是本应用的问题。

### 9.5 灯绳提示每次进书都弹、无法关闭 —— 已修
- 提示改为**持久化**：只在首次使用应用时出现一次（onboarding prefs 新增
  `cord_hint_seen_v1`，该文件已在进程启动时预热，无首帧 I/O）。
- 气泡自带**关闭按钮**（✕）；拉一次灯绳也会一并消掉提示。
- 真机验证：点关闭 → 气泡消失；杀进程重进 → 不再出现。

### 9.6 书架进度「第1章」恒定不变 —— 已修（三处保存点）
- 根因：TXT/Markdown 的进度 JSON 里 `ci` 恒写 0（locator 设计把 TXT 视为单章），
  而书架章号正是读它。三个保存点全部改存真实章号：
  ① 分页防抖保存 ② 滚动防抖保存 ③ **退出阅读器保存**（最后一次落库，漏了它前两处白做）。
- 章号来源：全书 `chapterStartOffsets` 二分反推（与保存的 offset 自洽）；
  小 TXT 分页下该列表为空（`bookIndex` 只从 EPUB 构建），退回
  `pagedSource.chapterIndexFor` / 会话章号。
- 恢复端不受影响：TXT 续读只读 `legacyOffset`，不读 `ci`（已核对全部消费方）。
- 真机验证：读到第 3 章回书架 → 显示「**第3章** · 37%」；单章测试书显示「第1章 · 6%」。
  注意：**旧进度**要等用户再读一次（触发新保存）后章号才会刷新。

### 9.7 翻页「停顿一下才翻」—— 已修（两处）
- ① `turning` 标志在提交帧保护的两帧等待期间仍为 true，期间的点按被直接吞掉
  → 改为等待移出 turning 窗口（保护本身保留）。
- ② `ensureBitmaps()` 在动画已开始后原地等 3 帧 —— 但捕获页只挂在静止态，
  动画中邻页**不可能补录**，等待纯属白停（每帧 16ms，最多 3 帧）。
  改为：录好了立即抓，没录好立即走实时兜底分支（渲染正确）。

## 10. 进度条统一美化（2026-09-19 追加）

用户反馈「阅读菜单进度条与设置子页滑杆不够美观」。排查结论：

- 全应用共 **8 处**滑杆，全部是原生 M3 `Slider`；设置页的（字号 / 页边距 / 目标分钟 /
  AI 温度等）带 `steps`，M3 会把轨道按步进切成「缺口 + 短段」——步数多时渲染成一排碎点
  （截图确认），即「不够美观」的直接来源；阅读菜单进度条则是默认样式（4dp 细轨 + 圆拇指）。

**方案**：新建统一组件 `ui/components/CraSlider.kt` —— 用 M3 1.3 的 `thumb` / `track`
槽位整体重绘，**手势、步进吸附、无障碍（ProgressBarRangeInfo）仍全部由 M3 承担**：

- 轨道：连续圆角条（6dp，不再碎段）；已走段 = tint，未走段 = onSurface 10%；
- 末端停点小圆（M3 Expressive 细节）；已走段外圈一圈细描边增加体积感；
- 拇指：20dp 圆，surface 底 + 2.5dp tint 描边；按住 1.15 倍弹簧放大（reducedMotion 关闭）。

**接入（8 处全部换用）**：`CompactSliderRow`（全部设置子页）、`SettingSliderRow`
（阅读设置子页：字号 / 页边距 / 亮度 / 护眼 / 节奏等）、`ReaderChrome`（阅读菜单全书进度）、
`ReaderProgressSheet`（进度跳转面板）、`ReaderTtsBar` ×3（语速 / 音调 / 音量）、
`AiSubPage`（温度）、`GoalSubPage`（目标分钟）。`Components.kt` 的 `RangeRow` 为死代码未动。

**真机验证**：阅读菜单进度条与设置页字号 / 页边距滑杆均为连续轨道 + 描边圆拇指 +
末端停点，两处视觉语言一致；拖动跟手、松手吸附档位正常。门禁同 9.8（2515 / 0 fail）。
