## 执行与结果

### 1. 产品目标与范围

产品应提供两条可独立使用的本地工作流：

- 桌面创作：创建/导入作品 → 卷章场景/大纲 → 正文与自动保存 → 全局卡片/资料引用 → 搜索/版本恢复/导出。AI由用户配置，结果先评审，不能直接覆盖正文。
- Android阅读：授权目录或文件导入 → 书架管理 → TXT/EPUB/Markdown阅读 → 搜索、笔记、灵感、TTS → 退出重进与位置恢复 → 安全备份/恢复及已有LAN协同。
- 共同底线：保护已有正文、位置、标注和创作资产；故障可识别、数据可恢复；有清楚的版本输入和证据。

历史候选清单不自动变成承诺：新增服务端、多人协作、手机创作项目双向编辑、全量视觉改造等不进入本轮队列。已授权能力不因低引用/旧报告分类而被永久取消。公开发布另有授权与退出条件。

### 5. 大任务完成后的固定复盘

大任务指可交付的功能闭环、阶段退出、联合验收或集成里程碑；单个断言/文案/报告补正不自动算新大任务。

流程：需求/里程碑 → 冻结输入和所有权 → 独立实施/准备 → 依赖到位后串行集成/设备验收 → Codex核原始证据 → 里程碑复盘 → 更新当前计划 → 派下一批。

每次复盘回答六件事，结果采用“保留/合并/重排/返修/待产品决定”，不能以复盘为由重新全量调查：

1. 交付的用户行为是否满足原需求；是否出现实测新风险或验收范围遗漏？
2. 下一任务是否仍必要，有没有已经交付、重复根因或只有报告措辞的问题？
3. 依赖、共享所有权、实际模型/额度和设备条件是否变化，能否合并验证或并行？
4. 哪些旧证据仍可复用；新增验证针对哪个具体变化或风险？
5. 当前版本的退出条件/分母是否变化？调整记录日期、原因、来源和影响，不改分母制造进度。
6. 下一批明确交付物、范围和停止点是什么？重要取舍/不可逆动作仅在需要时由用户决定，常规重排直接实施。

简报固定包含：本里程碑结果、计划保留/调整及原因、剩余关键路径、下一批与可复用证据、分范围百分比。复盘记在项目现态或本规划有关段落，实质改变才新增决策报告；不每次新建一套看板/自动任务。
