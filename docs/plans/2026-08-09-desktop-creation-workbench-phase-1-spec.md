# desktop — 创作工作台第一阶段正式规格

状态：**已确认功能边界，待实现**  
日期：2026-08-09  
适用产品线：Electron 桌面端（`src/`、`electron/`）  
目标平台：Windows 10/11 x64  
阶段名称：可靠写作闭环

> 本文取代 `docs/superpowers/specs/2026-06-29-inspiration-reading-workbench-design.md` 中“桌面端不承担正文写作”的产品决策。旧文档仅保留为历史快照，不再是实现依据。

## 1. 目的

把现有“阅读 + 灵感 + AI”桌面应用重构为单作者、本地优先的长篇创作工作台。第一阶段必须在不依赖新 AI 架构的前提下，安全完成以下闭环：

1. 创建或导入作品；
2. 组织卷、章节和场景；
3. 编写并自动保存正文；
4. 管理大纲、卡片、关系、批注和引用；
5. 搜索、重组、恢复和导出作品；
6. 从旧灵感和旧阅读器平滑迁入新工作流。

第一阶段完成后，即使用户不配置 AI，也能把应用作为正式写作工具长期使用。

## 2. 已确认的产品边界

### 2.1 定位

- 桌面端主线是“作品项目 + 正文写作 + 结构化创作资料”。
- 阅读主要在原生 Android 端完成；桌面端旧阅读器降为资料阅读入口。
- 单作者、本地优先，不需要账号或服务端即可完成全部第一阶段功能。
- 单项目性能基线：约 300 万汉字、2000 个卷/章/场景节点、10000 张卡片。

### 2.2 第一阶段明确不做

- OpenAI、Anthropic、Gemini 三协议的新供应商体系；
- AI 任务路由、上下文包、AI 重排和证据化一致性检查；
- 故事时间线、情节线与伏笔看板；
- PDF、DOCX、网页的应用内资料阅读；
- 手机端项目同步或双向编辑；
- 平台登录、自动发布或浏览器代发；
- 实时多人协作；
- Word 式完整富文本、自由节点画布、公式字段或脚本字段。

现有单一 OpenAI-compatible 灵感加工能力可作为兼容功能保留，但不得扩大为新 AI 架构，也不得直接覆盖正文或卡片。

## 3. 信息架构

### 3.1 应用级导航

1. 项目
2. 收件箱
3. 资料阅读
4. 全局搜索
5. 设置

应用启动后进入作品项目首页，显示最近项目、继续写作、目标进度和待处理收件箱。不得继续用阅读统计主导首页。

### 3.2 项目级导航

1. 概览
2. 写作
3. 大纲
4. 卡片
5. 统计
6. 版本历史

### 3.3 写作区

- 左栏：卷、章节和场景树；
- 中栏：连续滚动的结构化正文编辑器；
- 右栏：场景信息、卡片引用、批注与兼容 AI 候选；
- 左右栏可独立收起；专注模式只保留正文和必要状态。

## 4. 领域模型与不变量

### 4.1 核心实体

| 实体 | 关键内容 |
|---|---|
| Project | 标题、简介、结构模板、目标、主字数口径、工作流配置、归档状态 |
| Volume | 稳定 ID、项目 ID、标题、显示顺序 |
| Chapter | 稳定 ID、卷 ID、标题、自动/覆盖编号、状态、目标字数、发布记录 |
| Scene | 稳定 ID、章节 ID、标题、显示顺序、正文块、结构化场景字段 |
| DocumentBlock | 普通段落、场景分隔、引文/信件、居中文本、作者注 |
| CardType | 内置或自定义类型、字段 schema、版本 |
| Card | 项目 ID、类型、主名称、别名、字段值、标签、附件 |
| RelationType | 正向名称、反向名称、允许的起点/终点卡片类型 |
| CardRelation | 起点卡片、关系类型、终点卡片、可选说明 |
| TextAnchor | 场景、块、选区定位、引用对象、锚点状态 |
| Comment | 锚点、正文、关联卡片、待处理/已解决状态 |
| Snapshot | 对象类型、对象 ID、原因、内容摘要、创建时间、保留层级 |
| WritingSession | 项目/场景、活动时长、空闲时长、字数变化、时间范围 |
| PublicationRecord | 平台、发布时间、平台章节号/链接、发布字数、快照 ID |
| Asset | 项目 ID、哈希、内部路径、原始文件名、来源、引用计数 |
| InboxItem | 旧灵感或手动收集内容、来源、旧状态、候选版本、处理状态 |

### 4.2 强制不变量

1. **场景拥有正文。** 章节只聚合有序场景，不得再保存另一份并行章节正文。
2. 新章节自动创建一个默认场景，作者可以立即写作。
3. 卷、章节、场景、卡片和资源均使用不可变稳定 ID；排序、改名和跨卷移动不得改变 ID。
4. 卡片只属于一个项目；跨项目复用只能复制，第一阶段不建立实时共享关系。
5. 卡片引用和批注是非导出的锚点元数据，不占用正文字符。
6. 改卡片主名称不得自动替换正文；正文修改必须走可预览的查找替换。
7. 模板删除字段时先归档旧值；字段类型转换必须先预览、报告失败项并创建快照。
8. 删除默认是软删除并进入 30 天回收站；永久删除必须二次确认并说明关联影响。
9. 附件复制进项目资源库，以内容哈希去重；外部原文件不得被修改或删除。
10. 所有危险批量操作必须先创建保护快照，包括全项目替换、批量重排、模板迁移、旧稿导入确认和恢复。

## 5. 功能规格

### 5.1 新建项目

使用轻量三步向导：

1. 选择空白、结构模板或旧稿导入；
2. 填写标题、可选简介和题材；
3. 设置总字数、日/周目标、目标日期、每周更新日和章节工作流。

内置结构模板仅包含：空白、分卷长篇、连续连载。模板不得预填玄幻、悬疑、言情等题材套路。

### 5.2 卷章与场景

- 支持新建、改名、拖动排序、跨卷移动、复制和软删除；
- 支持按场景边界或光标位置拆章；
- 支持合并相邻章节；
- 支持批量修改状态；
- 操作前预览编号和引用影响；
- 章节编号与标题分离，支持序章、番外、手动覆盖和已发布编号锁定；
- 默认流程为：规划、待写、写作中、初稿、修订、定稿、已发布；项目可修改名称、顺序和颜色。

### 5.3 场景规划

每个场景可记录：

- 视角角色；
- 时间或相对时间；
- 地点；
- 出场卡片；
- 目标、冲突、结果；
- 情绪；
- 目标字数。

第一阶段不把场景继续拆成叙事节拍。

### 5.4 正文编辑器

- 连续滚动，不做实时纸张分页；
- 支持当前行聚焦、打字机滚动和专注模式；
- 支持普通段落、场景分隔、引文/信件、居中段落和作者注；
- 行内只支持有限强调和批注；
- 不支持表格、正文图片、任意附件、代码块或网页嵌入；
- 普通粘贴仅保留允许的结构；复杂或大段富文本先显示清洗预览；提供纯文本粘贴快捷键；
- 自动保存是主路径，界面持续显示“正在保存 / 已保存 / 保存失败”；`Ctrl+S` 强制落盘但不创建命名里程碑；
- 未正常退出时，重启后必须恢复已确认落盘内容，并对未完成写入给出恢复说明。

### 5.5 卡片与关系

内置八类卡片：角色、地点、组织、物品、世界规则、情节事件、伏笔线索、资料。

自定义字段支持：

- 单行文本、多行文本；
- 数字；
- 日期或相对时间；
- 单选、多选、布尔；
- 卡片引用；
- 网址；
- 附件。

字段可设置必填、顺序和默认值。关系类型可自定义正向/反向名称及适用卡片类型。卡片主名称和别名均参与搜索与提及识别。

### 5.6 大纲

- 树形视图管理卷、章、场景层级；
- 卡片板按章节或状态展示场景；
- 两种视图共享同一数据和排序；
- 拖动后正文聚合顺序、编号、引用和统计同步更新；
- 第一阶段不提供自由节点画布。

### 5.7 引用与批注

- 输入 `@` 搜索卡片后，在选区或段落建立非正文引用锚点；
- 引用标记在编辑器可见，但默认不进入成稿导出；
- 批注可锚定选区或段落、关联卡片，并标记待处理/已解决；
- 编辑导致锚点无法确定时，不得静默删除；应进入“待重新定位”列表。

### 5.8 搜索与替换

- 全局搜索覆盖项目、章节、场景、卡片、收件箱和资料；
- 项目搜索可按范围、类型、状态、标签、角色和来源筛选；
- 查找替换支持场景、章节、卷或项目范围；
- 默认普通文本；高级模式可启用受限正则；
- 替换前展示全部命中和差异，可逐条排除；
- 项目级替换前自动快照；不得执行自定义脚本。

### 5.9 版本、回收站与备份

- 自动快照采用分层保留：近期密集，随后折叠为每日和每周；
- 命名里程碑永久保留；
- 支持场景、章节、大纲节点和卡片的对象级差异预览与恢复；
- 整项目恢复仅用于灾难恢复，执行前再创建保护快照；
- 回收站默认保留 30 天；清空或立即永久删除需要二次确认；
- 用户选择独立备份目录后，每日和重大升级前自动生成校验备份；失败必须显著提示；
- 项目包和备份可选口令加密，界面必须说明忘记口令无法恢复。

### 5.10 创作目标与统计

- 项目总字数、每日/每周字数、目标日期和每周更新日；
- 同时计算汉字数、非空白字符数、含标点字符数；项目选择主指标；
- 活动会话只在输入、选择或结构操作时计时，空闲超时暂停；
- 用户可查看并修正会话；不得记录具体按键内容；
- 统计包括日/周净增、修订量、活动时长、连续写作、章节状态和里程碑。

### 5.11 本地校对

纯本地检查以下问题，只提示、不自动修改：

- 连续重复字；
- 成对标点；
- 异常空格和段首格式；
- 超长段落；
- 用户自定义禁用词。

### 5.12 发布记录

不连接发布平台。章节可手动记录平台、发布时间、平台章节号或链接、发布时字数和对应快照。本地稿在发布后继续修改时显示“与已发布版本不同”。

### 5.13 导入、导出与项目便携

- TXT、Markdown、DOCX 旧稿导入先预览卷章识别结果，允许调整后创建新项目；第一阶段不直接合并覆盖已有项目；
- CSV 行可映射为卡片，Markdown 标题块可映射为卡片；导入前预览字段、类型和关联，默认只新增；
- 卡片可按筛选范围导出 CSV 与 Markdown；
- 成稿导出提供“平台发布净文本”和“标准审阅稿”两类预设；
- 完整项目包包含正文、大纲、卡片、关系、快照、资源和必要元数据，可校验并完整重新导入；
- 项目包格式必须版本化，不得依赖原电脑绝对路径。

### 5.14 旧功能衔接

- 旧 TXT、Markdown、EPUB 书库和阅读器继续工作；
- 第一阶段只调整导航，并增加“摘录到项目资料卡 / 全局收件箱”；
- 阅读摘录必须保存不可变来源快照，并尽量保留原 `bookId` 与 locator；
- 旧单一 OpenAI-compatible 灵感动作继续生成候选版本，不直接覆盖新正文或卡片。

## 6. 存储 module 与 interface 约束

### 6.1 为什么不能继续把新项目塞进单个 JSON

当前桌面端以原子 JSON 写入、`.bak`、进程内文件锁和目录备份保护 `inspirations.json`、`library.json` 等数据。这些机制必须继续保护旧数据，但新项目需要事务、关系完整性、全文索引、对象级快照和目标规模查询，不能通过不断扩大的整文件读写实现。

### 6.2 外部 seam

主进程应提供一个深的 `CreationWorkspace` module。renderer、迁移器、导入器和测试只跨以下概念 interface：

- `read(query)`：读取项目、树、场景正文、卡片、搜索和统计视图；
- `transact(command)`：在一个事务内执行写作、重排、关系、快照、回收站和恢复命令；
- `watch(scope)`：订阅已提交变更，不暴露底层表或文件；
- `check()`：返回 schema、关系、资源、索引和快照完整性报告。

项目包、旧数据迁移和自动备份分别作为独立深 module，通过上述 interface 读写，不得绕过它直接操作底层存储。

### 6.3 实现选择门槛

本文不提前锁定具体数据库或编辑器依赖。实现前必须用候选 adapter 完成 Windows 开发态、生产构建、NSIS/免安装包、备份恢复和目标规模压力 spike。只有满足以下条件的 adapter 才能进入实现：

- 事务与崩溃恢复可验证；
- 支持所需索引与全文检索，或能与独立索引可靠组合；
- Electron 打包、升级和迁移路径明确；
- 测试可使用临时目录或内存 adapter；
- 不要求 renderer 直接访问磁盘或数据库。

## 7. 旧数据迁移要求

### 7.1 当前来源

迁移器至少识别：

- `app-settings.json`；
- `inspirations.json`；
- `ai-secrets.json`（只保留原位置，由兼容 AI 使用，不复制明文）；
- `AppLibrary/library.json`；
- `AppLibrary/highlights.json`；
- `AppLibrary/bookmarks.json`；
- `AppLibrary/reading-progress.json`；
- 旧书库文件、封面和搜索索引。

### 7.2 迁移流程

1. **预检**：检查数据目录可读写、剩余空间、旧文件可解析性和目标 store 状态；
2. **升级前备份**：创建独立、带 manifest 与校验和的完整备份；备份失败则不得开始迁移；
3. **复制构建**：在新临时目录构建项目 store，旧文件保持不变；
4. **灵感迁移**：每条旧灵感进入全局收件箱，保留 ID 映射、标题、正文、类型、状态、标签、平台标签、来源、revision、时间戳和全部 AI 候选；
5. **阅读数据兼容**：书库与阅读记录不复制成项目卡；原数据继续由旧阅读 module 使用；只有用户执行“摘录到项目”时才创建资料卡和来源快照；
6. **校验**：比较条目数量、正文哈希、候选数量、来源字段和 ID 映射，运行关系与资源完整性检查；
7. **切换**：新 store 通过校验后才写入激活指针；
8. **兼容期**：旧数据只读保留，迁移报告和备份路径可见；
9. **失败回退**：任何失败都删除未激活的临时 store，继续使用旧数据，不得留下半迁移状态。

### 7.3 迁移报告

报告必须包含：

- 备份路径、manifest 版本和校验结果；
- 发现、迁移、跳过、失败的条目数；
- 每个失败项的旧 ID、原因和可重试建议；
- ID 映射文件；
- 新 store 完整性检查结果；
- 是否已经激活、如何回退。

报告不得记录真实书名之外的测试书目内容；自动化测试和文档只使用“测试 EPUB”“测试 TXT”等中性名称。

### 8.4 安全与隐私验收

- renderer 不获得任意文件系统读写能力；
- 所有导入、导出和资源路径在主进程校验，禁止路径穿越；
- API Key 不进入项目包、备份明文、日志或 renderer 状态；
- 加密项目包不会在错误口令时产生部分解压目录；
- 调试导出默认不包含正文、卡片正文、附件或 API Key；
- 本地校对和写作计时不上传内容，不记录具体按键；
- 全部破坏性操作有明确目标、影响说明和恢复路径。

## 9. 建议实施切片

每个切片必须独立通过现有桌面构建与相关新门禁，不允许先铺满空页面再集中接数据。

1. **存储 adapter spike 与门禁**：比较候选事务存储和编辑器 adapter，验证 Windows 开发/打包/升级/压力路径；只输出决策与最小测试。
2. **CreationWorkspace module**：实现 schema、事务、完整性检查、临时目录 adapter 和最小命令/查询 interface。
3. **只读迁移审计**：读取旧数据、生成迁移计划和报告，不激活新 store。
4. **项目壳与新建闭环**：项目首页、两级导航、三步向导、首章默认场景。
5. **场景正文编辑闭环**：结构化块、连续滚动、中文 IME、自动保存、崩溃恢复和基础快照。
6. **卷章与大纲**：树、卡片板、安全拆并移、编号和工作流。
7. **卡片深 module**：类型、字段、关系、别名、附件、引用和批注。
8. **历史与数据安全**：分层快照、对象恢复、回收站、自动备份和完整性门禁。
9. **导入导出与项目包**：旧稿、卡片、成稿和完整项目包。
10. **搜索、统计和键盘效率**：双层搜索、替换、命令面板、目标、会话和本地校对。
11. **旧数据激活迁移与旧功能衔接**：复制迁移、回退、旧阅读摘录、兼容 AI 候选。
12. **目标规模与发布验收**：全量门禁、压力测试、Windows 安装版/免安装版和人工数据恢复演练。
