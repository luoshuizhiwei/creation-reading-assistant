# desktop — Novalist 功能取舍记录

状态：**候选池，不是当前实施任务**  
记录日期：2026-08-21  
参考仓库：<https://github.com/xiauho/novalist>

## 1. 结论

Novalist 与本项目相似的部分仅限 Electron 桌面创作工作台；它不是原生 Android 阅读端的
实现参考。该仓库截至记录日只有两次提交、无 Release，适合作为产品概念草图，不应作为技术
成熟度或数据安全能力的证明。

采用原则：**借交互概念，不搬 PySide6 代码，不替换现有 SQLite/IPC/事务架构。**

## 2. 已确认功能

- 本地 Markdown/JSON 小说项目；章节、大纲、角色、世界观、战力体系和时间线。
- 纯文本写作、查找替换、实时统计、自动保存、未保存提示和专注模式。
- 「故事雷达」聚合章节目标、出场角色、故事状态、章节摘要和未回收伏笔。
- 外部 `dsh --profile headless` 驱动续写、一致性检查、摘要和故事状态更新。
- 首次 AI 调用前说明可能发送的数据；AI 结果需用户审阅。
- Markdown/TXT 整书导出。

## 3. 与本项目的差异

本项目 desktop 已有卷—章—场景、大纲双视图、场景规划、可扩展卡片与关系、批注/引用、
项目级搜索替换预览、revision、事务、快照/回收站、项目包和完整性检查。Novalist 的普通写作、
保存、统计、专注与导出能力不构成新的路线图项目。

Novalist 的直接文件覆盖、JSON 损坏时回退默认值、文件名排序、角色名子串匹配、全量塞入
世界观/战力上下文，以及 AI 状态字典合并，均不满足本项目的数据与规模不变量。

## 4. 值得采用的候选

### D-C1 创作雷达 v1（优先，P1 兼容）

把 `src/features/creation/editor/WritingDesk.tsx` 右侧「场景信息」扩展成两个页签：

1. 场景雷达：视角、时间、地点、出场、目标、冲突、结果、情绪、目标/当前字数、引用卡片、
   未解决批注、伏笔卡和 revision。
2. 批注与引用：保留当前批注、重新定位、关联卡片与 `@` 引用能力。

首片只聚合已有 `outline`、`selectedScene`、`sceneView`、`cardList`、`annotations`；不新增表，
不调用 AI，不改变正文。必须覆盖项目/场景快速切换的迟到响应隔离、专注模式和窄屏行为。

### D-C2 AI 上下文预览（P1 完成后）

每次 AI 任务展示将发送的场景、卡片、设定和摘要，可按组排除并显示字符数或预估 token。
输出只进入候选版本；接受前显示差异，校验当前 revision，危险批量写入前创建保护快照。

现行 P1 规格明确不扩建 AI 路由、上下文包和证据化一致性检查，因此本项不得提前插入 P1。

### D-C3 结构化连续性台账（长期候选）

角色状态、位置、物品、关系、事件和伏笔应建立在卡片/关系/场景规划之上。模型只能生成带
来源和差异的提案，不能直接修改 canonical 数据；伏笔必须有 open/resolved 生命周期，不能
用旧、新列表简单并集。

## 5. 明确拒绝

- 用 Markdown/JSON 取代 `CreationWorkspace`。
- 在 desktop 引入第二套 Python/PySide6 运行时。
- 绑定 DeepSeek Harness 或硬编码网文/战力体系。
- 角色名子串作为唯一上下文召回依据。
- AI 续写直接覆盖正文，或只验证返回值是 JSON object 就写入长期状态。
- 把上述候选扩散到 `android/`；移动端只在未来通过稳定的数据契约消费阅读摘录/来源快照。

启动 D-C1 前先确认 desktop P1 当前门禁仍全绿且工作区没有并行 desktop 所有者；实施后运行
`npm test -- --run`、相关 creation contracts、`npm run build`、desktop Beta 和
`git diff --check`。D-C2/D-C3 必须另立正式设计与验收，不以本调研记录直接开工。
