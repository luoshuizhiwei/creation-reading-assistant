# S04 WorkManager 真机方案独立复核

- 日期：2026-09-25
- 输入：`docs/qa/2026-09/2026-09-25-s04-workmanager-safe-device-plan.md`
- 性质：只读审查；未运行 adb、未安装、未触碰真机或原书。
- 结论：**BLOCKED，不批准按当前方案启动真机 instrumentation。** 离线测试 APK 编译通过不等于正式数据安全。

## 必须修正的边界

1. **P1：方案将 WorkManager 副作用写成必然且有界，证据不足。** §2.2/§13 D2 声称任务必然被认领、最多三次失败、下次打开自动恢复，并称避免它的唯一办法是取消任务。这些是源码路径推测，不是设备实测；队列是否已有待执行任务、执行时间、系统调度和测试进程行为均未核对。即便一个索引任务可重新入队，也不能等同于原有任务状态及用户设备状态自动复原。不得以用户接受“固有副作用”替代技术隔离或基线取证。优先离线设计不触碰现有 workdb 的测试入口；若做不到，向用户明确报告无法无副作用验收。
2. **P1：§4 把 W1 的 workdb 变化一律归因 instrumentation、把 W2 无变化当成判据，均过强。** 时间窗只提供相关性；不能单凭目标 App 未在前台就排除系统调度或别的进程。W2 有自然调度也不必然表示异常。应将无法逐条证明来源的变化标为 UNATTRIBUTED / BLOCKED，不用时间窗推断覆盖证据缺口。
3. **P1：§8 直接 `adb install` 和签名冲突时自动卸载测试包，不符合项目既定安装与设备状态边界。** 将来获准验机时应先用 `android/scripts/install_with_confirm.ps1` 并保存失败原始证据；直接 ADB 仅在脚本真实失败后作为明确标注的功能验收回退。卸载已有测试包是另一项设备写操作，不能预授权为自动回退。
4. **P1：§9 第 4 级“全量 androidTest”超出已审计测试集合。** 报告自己承认其中有会写 `databases/` 的旧测试，§13 D3 又允许偏好文件副作用；不能以白名单笼统批准全量运行。先逐类审计写入路径，形成明确的最小允许列表；有未隔离的类就停在定向测试，不运行全量。
5. **P2：跑前 tar 不是自动可信的恢复点。** 在线复制 Room/WorkManager 的 WAL 三件套并不保证同一时刻一致，`integrity_check` 通过也不证明业务状态原子一致；还要明确私有备份目录、访问控制、保留/清理期限，避免把用户书库内容或真实书名写入仓库证据。未拿到可复核一致性时不把它称为可恢复点。

## 可保留的部分

- 只操作恢复仓库构建产物、确认真机 serial 与竖屏、避免 MuMu；不重装主 APK、不使用 `connectedDebugAndroidTest`；新鲜构建与 APK 哈希闭合。
- 对正式 Room 表、索引、文件、偏好、workdb 做前后对账；原书字节不变是硬门槛。上述取证仍需审查具体命令及权限，不授权本报告直接执行。
- 用户决定之前不运行任何设备写操作，也不自动 force-stop、卸载、取消 WorkManager 或恢复数据。

## 下一步

先做离线窄范围设计：调查能否在不消费既有 WorkManager 队列、不中断正式 App、不运行有副作用测试类的前提下验证 Runner / EPUB 隔离。给出可执行的最小测试列表和明确停机条件；不能做到则保留 BLOCKED，并请用户决定是否接受带设备状态变化的验收。当前方案的三个用户问题并非充分放行条件。
