# 前端优化项目说明文档（供 Perplexity 生成优化提示词使用）

> 本文档描述一个移动端阅读器 App 的前端现状，供 Perplexity 据此生成针对性的前端优化提示词。
> 优化目标：**视觉层次、信息密度、交互流畅度、组件排列、移动端适配**的全面打磨。
> **只优化移动端（mobile 目录），不涉及桌面端。**

---

## 一、项目概况

### 1.1 定位
- 名称：创作阅读助手（移动端）
- 类型：本地阅读器 + 灵感收集 + 阅读统计 + AI 辅助
- 支持格式：EPUB（epubjs 渲染）、TXT、Markdown
- 参考产品：微信读书、起点读书、Reeden、开源阅读（Legado）

### 1.2 技术栈
- React 18 + TypeScript
- Capacitor 6（Android 打包）
- Vite 5 构建
- epubjs（EPUB 渲染）
- SQLite（本地存储）
- 纯 CSS（无 Tailwind / CSS-in-JS），通过 CSS 变量构建设计令牌系统
- lucide-react 图标库

### 1.3 架构特点
- **单 state 切换式路由**（非 React Router），通过 `tab` state 在 5 个主 Tab 间切换
- 阅读器为全屏覆盖视图（`readerBook` 非空时整屏切换）
- 所有页面共享一个 `MobileSnapshot` 数据快照
- Zustand stores 管理全局状态

## 二、页面结构清单

### 2.1 主导航结构

```
<main className="mobile-shell">
  <section className="phone-page">  ← 当前 Tab 页面（条件渲染）
    HomePage | ShelfPage | InspirationPage | StatsPage | ProfilePage
  </section>
  <nav className="bottom-nav">      ← 底部 5 Tab 导航
    首页(Home) | 书架(BookOpen) | 灵感(Sparkles) | 统计(BarChart3) | 我的(User)
  </nav>
  ← 浮层：GlobalSearchOverlay、OnboardingOverlay、ConfirmDialog、Toast、QrScanOverlay
</main>
```

**底部导航**：`position: fixed; bottom: 0; height: calc(64px + safe-area)`，5 个按钮（图标 + 文字），激活态有胶囊背景。Profile 二级页时隐藏。

### 2.2 五个主 Tab 页面

#### ① HomePage（首页）
**职责**：阅读概览与快速入口

**当前布局（自上而下）**：
1. `header.mobile-header` — 左侧「今天 / 首页」标题，右侧圆形全局搜索按钮（44px）
2. `section.home-summary-row` — 两张并排摘要卡（累计本数、阅读时长），2 列网格
3. `section.home-goal-card`（条件）— 每日目标卡：进度条 + 提示
4. `section.home-section` — 「继续阅读」横向滚动条（`continue-strip` + 多个 `continue-card`，每卡含封面 + 进度）
5. `section.home-reading-status-card` — 同步状态卡
6. `section.home-inspiration-mini` — 灵感入口 + 右侧 + 按钮

**痛点**：
- 摘要卡信息密度低，两张卡只显示数字 + 标签
- 「继续阅读」横滑条卡片宽度 `min(100%, 352px)`，大屏下单卡占满，小屏需滑动
- 灵感入口与首页其他区块视觉权重不分明

#### ② ShelfPage（书架）
**职责**：书架管理，含搜索/筛选/排序/网格列表/批量/导入

**当前布局**：
1. `header` — 「本地书库 / 书架」+ 右侧动作组（管理 / 导入历史 badge / 导入）
2. `section.import-queue-card`（条件）— 导入进度
3. **非多选模式**：搜索框 → 藏书统计 → 工具栏（排序下拉 + 网格/列表切换）→ 三组筛选 chip 横滑（书单/分类/标签）→ 筛选摘要
4. `section.book-grid`（网格）或 `.book-list`（列表）— 渲染 `BookTile`
5. `p.center-foot` — 底部计数
6. `nav.shelf-batch-bar`（多选时）— 批量操作底栏
7. 底部 Sheet：批量管理 / 导入历史

**痛点**：
- 顶部层级多（搜索 + 统计 + 工具栏 + 三组筛选），首屏信息过载
- 三组筛选 chip 横滑占用大量垂直空间
- 网格与列表切换后视觉差异大，列表模式信息排列松散

#### ③ InspirationPage（灵感）
**职责**：灵感收集与批量管理

**当前布局**：
1. `header` — 「先收进箱子…/灵感」+ 导出按钮 + 模板按钮
2. `section.quick-note-card` — 快速记录卡（标题输入 + 正文 + 标签 + 保存按钮）
3. `label.search-pill` — 搜索框
4. `section.inspiration-filter-bar` — 状态 chip 横滑 + 分组切换（状态/来源/平铺）+ 批量按钮
5. `section.inspiration-list` — 三种渲染：按来源分组 / 按状态分组 / 平铺，每项为 `InspirationCard`
6. `nav.inspiration-batch-bar`（多选时）— 批量操作底栏
7. `div.inspiration-template-panel`（条件）— 模板底部 sheet

**痛点**：
- 快速记录卡占据首屏较大空间，挤压灵感列表可见性
- 灵感卡片（`compact-inspiration-card`）信息层次：标题 1 行 + 预览 1 行 + meta 标签，排列偏紧凑但缺少视觉锚点

#### ④ StatsPage（统计）
**职责**：阅读统计可视化

**当前布局**（内容最丰富的页面）：
1. `header` — 标题 + 圆形「回到当前周期」按钮
2. `div.range-tabs` — 周期切换（日/周/月/年/全部）
3. `div.stats-period-title` — ‹ 周期标题 ›翻页
4. **数据区**（大量卡片纵向堆叠）：
   - 概览卡（8 个指标 2×4 网格）
   - 连续阅读卡（当前 + 最长）
   - 年度目标卡（目标数 +/- 调整 + 进度条）
   - 周期对比卡
   - 阅读时间趋势卡（`heat-bars` 柱状图）
   - 年度热力图卡（365 天网格 + 图例）
   - 24 小时分布卡（24 根柱）
   - 阅读时间线卡
   - 阅读时长排行榜卡
   - 灵感与笔记卡
   - 成就体系卡（8 个徽章 4 列网格）

**痛点**：
- 11+ 张卡片纵向堆叠，页面过长，缺乏分组与折叠
- 概览卡 8 个指标 2 列网格，数字 + 标签排列单调
- 热力图、柱状图、排行榜视觉风格不统一（有的有标题区，有的没有）
- 成就徽章 4 列网格偏小，图标 + 文字 + 进度信息拥挤

#### ⑤ ProfilePage（我的）
**职责**：设置与个人信息

**当前布局**：
1. `header.profile-topbar` — 标题 + 圆形「更多」按钮
2. `section.profile-more-panel`（条件）— 快捷入口浮层
3. `section.profile-card` — 用户卡（avatar + 设备信息）
4. `section.profile-grid` — 两个快捷按钮（同步 / 笔记）
5. 多个 `section.profile-menu-group` — 4 组菜单列表：
   - 数据管理（同步/备份/书单/分类/标签）
   - 工具（阅读设置/笔记/AI 助手）
   - 外观（主题外观）
   - 系统资源（存储/隐私/关于）
   每项：图标 + 标题 + 描述 + 可选 badge + 箭头

**二级页**（7 个）：SyncPage、WebDavPage、LibraryManagersPage、ReadingAndNotesPage、AISettingsPage、AppearancePage、AboutAndPrivacyPage
统一结构：`header.subpage-header`（返回按钮 + 标题）+ 多个 `section.subpage-card`

**痛点**：
- 菜单组之间视觉分隔弱，4 组平铺显得冗长
- 用户卡信息单薄（avatar + 设备名），可增加阅读数据摘要
- 二级页表单输入框样式统一但缺少分组标题

### 2.3 阅读器（MobileReaderView）
**全屏覆盖视图**，独立于 5 个 Tab

**布局层次**：
1. `div.reader-dim-layer` — 亮度遮罩
2. `header.reader-topbar` — 返回 + 书名/进度/时长 + 顶栏动作（听书/AI/搜索/更多下拉）
3. `section.reader-scroll-container` — 正文容器（滚动/翻页两种模式）
4. `div.reader-zone-guide` — 翻页区域提示（控件可见时）
5. `div.reader-toast` — 提示条
6. `section.reader-selection-toolbar` — 选中文字工具栏（高亮/灵感/笔记/搜索/复制）
7. 各类 Sheet：目录 drawer / 主题 / 设置 / 进度 popover / 灵感记录 / AI 辅助 / TTS 播放条
8. `footer.reader-bottom-sheet` — 底部 5 按钮（目录/进度/灵感/主题/设置）

**痛点**：
- 顶栏动作按钮多（听书 + AI + 搜索 + 更多），小屏拥挤
- 底部 5 按钮 + 进度 popover + TTS 浮条，层级复杂
- 选中工具栏与底部菜单可能同时出现，视觉冲突

## 三、设计系统现状

### 3.1 配色体系（Copper / Warm Paper 暖纸铜色基调）

**亮色主题**：
| 令牌 | 值 | 用途 |
|---|---|---|
| `--paper` | `#fbf7ef` | 主背景（暖纸色） |
| `--paper-2` | `#f0e6d8` | 次级背景 |
| `--ink` | `#211914` | 主文字 |
| `--muted` | `#76695f` | 次级文字 |
| `--copper` | `#8e5b2b` | 品牌铜色 |
| `--md3-primary` | `#8e5b2b` | 主色（直接写死，非 var(--copper)） |
| `--md3-surface-container-lowest` | `#fffdf8` | 卡片最低层 |
| `--md3-surface-container-low` | `#fff9f0` | 卡片低层 |
| `--md3-outline-variant` | `#eadfce` | 描边 |

**暗色主题**：
| 令牌 | 值 |
|---|---|
| `--paper` | `#17120f` |
| `--ink` | `#f8efe4` |
| `--copper` | `#d59a61`（变浅） |
| `--md3-primary` | `#8e5b2b`（**未重定义，暗色下偏暗**） |
| `--md3-surface-container-low` | `#1d1713` |

**已知问题**：
- `--md3-primary` 在暗色模式下未重新定义，仍为亮色的 `#8e5b2b`，在暗背景上对比度不足
- 半透明白色背景（如 `rgba(255,252,246,0.72)`）在暗色下会呈现亮色块，未单独覆写

### 3.2 字体系统
- **最终生效字体族**：`"MiSans", "HarmonyOS Sans SC", "PingFang SC", "Noto Sans SC", system-ui, sans-serif`
- （注：早期定义了 `LXGW WenKai Screen` 霞鹜文楷，但被 release-overrides 覆盖为 MiSans）
- **字号刻度**：body 16px，h1 `clamp(28px, 7.5vw, 34px)`，h2 19px，小字 11-12px
- 字重：标题 760-780，正文 400-600，按钮 600-650

### 3.3 圆角系统（不统一）
| 场景 | 当前值 | 令牌 |
|---|---|---|
| 通用卡片 | 22px | `--app-card-radius` |
| 通用控件 | 18px | `--app-control-radius` |
| 实际混用 | 16/17/18/19/20/22/24px | 未全部走令牌 |
| 按钮全圆 | 9999px | `--md3-shape-full` |
| 底部 sheet | 24px（顶部圆角） | 写死 |

### 3.4 阴影系统（双轨制）
- **MD3 elevation**（5 级）：定义完整但实际少用
- **当前主流**：`--app-soft-shadow: 0 10px 26px rgba(66,43,24,0.045)` 或 `box-shadow: none` + 1px 描边的扁平纸感
- 两套阴影语言共存，需统一

### 3.5 动效系统（不统一）
- **MD3 motion 令牌**：定义了 10 档时长 + 4 种曲线，但代码中混用具体数值
- **实际时长**：100/120/140/150/160/180/200/220/240/300/320ms 等散落各处
- **实际曲线**：`cubic-bezier(0.2,0.8,0.2,1)` / `ease` / `ease-out` / `ease-in-out` 与令牌混用
- **已支持** `prefers-reduced-motion`

### 3.6 移动端适配
- `env(safe-area-inset-*)`：全面使用（top/bottom/left/right）
- `100dvh / 100vw`：用于全屏布局与 sheet max-height
- `touch-action`：阅读器 `pan-y`（滚动）/ `pinch-zoom`（翻页）
- `backdrop-filter: blur()`：10+ 处使用，但 `-webkit-` 前缀不一致
- `scroll-snap-type`：继续阅读横滑条使用
- `-webkit-tap-highlight-color: transparent`：全局去除点击高亮
- `@media (max-width: 390px)`：小屏适配
- `@media (prefers-contrast: more)`：高对比度适配
- 触摸目标：部分强制 44×44px，但仍有小图标按钮低于 44px

## 四、组件视觉模式

### 4.1 卡片（统一模式但执行不彻底）
**目标统一模式**：1px 细描边（`--app-hairline`）+ 22px 圆角 + 半透明纸色背景 + 柔和阴影
**实际情况**：各类卡片圆角混用 16-24px，背景透明度 0.66-0.82 不等

### 4.2 按钮
| 类型 | 样式 | 触摸目标 |
|---|---|---|
| 主按钮 | 铜色填充 + 白字 + 全圆 | 40px min |
| ghost-button | 透明 + 铜色字 + 全圆 | 44px |
| round-action | 圆形描边 + 半透明背景 | 42-44px |
| filter-chip | 描边胶囊 + 次级容器激活态 | 32px |
| view-toggle | 分段控件 | 36-44px |
| 底部 nav | 图标 + 文字 + 激活胶囊 | 50px |

### 4.3 底部 Sheet
- 统一结构：`reader-sheet-mask`（遮罩 z35）+ `reader-bottom-sheet-panel`（面板 z36）
- 顶部圆角 24px，grabber 把手，标题，内容区
- max-height 多为 72dvh

### 4.4 搜索框
- 统一为 `label.search-pill`：胶囊形 + 🔍 前缀 + input

### 4.5 筛选 Chip
- 统一为 `filter-chip-rail` + `button.filter-chip`（横滑，激活态加 `active`）

## 五、已知痛点汇总（供优化参考）

### 5.1 信息架构层面
1. **StatsPage 过长**：11+ 卡片纵向堆叠，无分组/折叠，用户需大量滚动
2. **ShelfPage 顶部层级多**：搜索 + 统计 + 工具栏 + 三组筛选，首屏信息过载
3. **HomePage 空间利用不足**：摘要卡信息密度低，继续阅读横滑条大屏下单卡占满

### 5.2 视觉一致性层面
4. **圆角不统一**：卡片混用 16-24px，未全部走令牌
5. **阴影双轨制**：MD3 elevation 与 app-soft-shadow 共存
6. **动效时长曲线散乱**：12+ 种具体值与令牌混用
7. **暗色模式主色过暗**：`--md3-primary` 未在暗色下重定义
8. **半透明白色背景在暗色下异常**：未单独覆写

### 5.3 交互细节层面
9. **阅读器顶栏拥挤**：听书 + AI + 搜索 + 更多，小屏按钮密集
10. **选中工具栏与底部菜单冲突**：可能同时出现
11. **部分触摸目标 < 44px**：小图标按钮不符合无障碍标准
12. **backdrop-filter 前缀不一致**：部分位置缺 `-webkit-`

### 5.4 组件排列层面
13. **灵感卡片缺少视觉锚点**：标题 + 预览 + meta 排列紧凑但无层次
14. **成就徽章网格拥挤**：4 列，图标 + 文字 + 进度信息挤压
15. **统计概览卡单调**：8 个指标 2 列，数字 + 标签无变化
16. **Profile 菜单组分隔弱**：4 组平铺，视觉分隔不明显

## 七、优化方向期望

希望 Perplexity 生成的优化提示词覆盖以下维度：

1. **信息架构重组**：特别是 StatsPage 的卡片分组/折叠、ShelfPage 的顶部层级精简、HomePage 的空间利用
2. **视觉层次强化**：卡片内信息的主次区分、标题/数字/标签的字号字重对比、留白与间距节奏
3. **组件排列优化**：网格列数、卡片宽高比、横滑条卡片尺寸、徽章/指标的可读性
4. **视觉一致性统一**：圆角令牌化、阴影策略统一、动效时长曲线标准化、暗色模式补全
5. **交互流畅度**：按钮反馈、Sheet 动画、页面切换、加载状态的过渡
6. **移动端适配加固**：触摸目标、safe-area、小屏（390px 以下）降级、backdrop-filter 前缀
7. **阅读器专项**：顶栏动作折叠、底部菜单与进度条集成、选中工具栏与底栏的冲突处理

## 八、约束条件

- **只改移动端**（`mobile/src/` 目录），不动桌面端
- **不改变功能逻辑**，只优化视觉与交互
- **保持现有 className 命名**，避免大规模重命名
- **保持 CSS 变量体系**，可扩展但不大改令牌名
- **构建命令**：`cd mobile && npx tsc --noEmit && npx vite build` 必须通过
- **Android WebView 兼容**：按钮 `:active` 反馈用 `transform: scale` 不用 background（背景会粘连）
