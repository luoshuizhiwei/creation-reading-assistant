# 文件交接与低开销监控协议

用户于2026-10-25明确授权将本协议加入workbuddy-deepseek-android自动化。此协议覆盖旧“每次通过UI粘贴完整长提示词”的传递方式；任务权限、唯一owner、证据和验收规则保持有效。

## 当前立即启用

- Root将完整任务保存为docs/coordination中的独立文档，正文保持一个至少四反引号的完整围栏。文件写完后计算SHA256，再派发；后续修改使用新修订，不能悄悄改变已派发文档。
- 发往既有Claude A/B会话的UI消息仅含任务编号/版本、绝对文档路径、完整SHA256、owner、必要停止提示。执行者读取该文档并核SHA后执行，无法读或SHA不符停报。无需再把正文经UI重复输入。
- 每次实际提交后最多一次确认已接收；可用原有执行者本地回执确认。UI提交状态不明，先读回执/当前UI，不能盲目重发。单纯“文件已保存”不能声称任务已提交或执行者已接收。
- 后续心跳只检查当前指定ready.json是否出现/发生变化；未变不重复读取报告、不截图、不打开会话、不制造状态询问。变化后只读对应REPORT和必要原件，核任务/输入指纹/证据后裁定。
- ready.json由执行者在完成报告和必要原件后最后写入。保留已有报告格式，含任务/版本、lane、状态、输入指纹或任务文档SHA、报告路径与sizeSHA、停止原因。现有任务回执充分时直接复用，不为新协议重做旧任务。
- Root记录本次已读ready指纹于当前交接的当前任务条目，或在既有自动化提示词中维护；不新增逐次心跳收据，不写私库记忆。只有ready变化或具体缺口才增加读取。
- 不用UI查看思考时长/停止按钮等普通busy状态；无进展且真实怀疑会话中断时才一次UI核对。无变化DONT_NOTIFY，真实失败同因不重复通知。

短消息格式（在真实UI发出；不是内部API）：

````text
任务<编号-版本>，owner <A/B>。请读取完整任务文档：<绝对路径>；SHA256：<完整64位SHA>。先核SHA一致，再按文档执行并交指定ready/REPORT。读不到、SHA不符、重复任务或权限不清即停报。完整指令以该冻结文档为准，不自动接续其他任务。
````

## 文件接力试点：尚未启用

下一次真正需要的普通离线任务，可附带一次有边界的接力验证。先确认执行者实际支持等候文件后接续，检查重复领取、SHA不符、停止信号及回执，不能假定Claude会话可永续运行。该试点不得单独触发构建/ADB/安装卸载/业务attempt，不能为验证协议制造无产品价值任务。

验证成功前，每个新任务仍用一次上述短UI消息派发；不建立后台服务、不循环唤醒模型、不用内部API或Claude私有存储。验证成功后Root再明确启用指定本地待办文件及范围；等待有截止时间，空等不得反复模型推理。文件出现不扩大任务权限，Root具体设备/恢复许可仍须逐批写明。
